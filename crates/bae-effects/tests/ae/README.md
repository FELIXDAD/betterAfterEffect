# 与 After Effects 对照（效果库）

| 文件 | 用途 |
|---|---|
| `cases.json` | 用例（两边共用）：输入图、效果 matchName、参数（按 AE 参数序号）、`tolerance`（允许的最大单通道差）、`mean`（允许的平均差），单位都是 8 位色阶。 |
| `render_cases.jsx` | 在 AE 里逐个建合成（输入图尺寸、8 bpc、不线性混合、无色彩管理、图层质量"最佳"），按 matchName 设参数，`saveFrameToPng` 输出第 0 帧。 |
| `harness.rs` | 生成输入图（不提交二进制素材），用 BAE 渲染同样的用例（8 bpc 语义）并比较。 |
| `golden/` | AE 26.2.1（macOS）的输出，`tests/ae_golden.rs` 在 CI 里用它比较，不需要 AE。软件 / 虚拟适配器（CI 的 WARP）上最大差加 2、平均差加 0.5。 |

重新生成：

```sh
cargo run -p bae-effects --example ae_compare -- prepare           # 输入图 + cases.json → /private/tmp/bae-07-ae
tools/ae/aectl run crates/bae-effects/tests/ae/render_cases.jsx    # AE → /private/tmp/bae-07-ae/ae
cargo run -p bae-effects --example ae_compare -- compare           # BAE 渲染 + 对比表
cargo run -p bae-effects --example ae_compare -- golden            # 把 AE 输出拷进 golden/
```

探针（拟合核和曲线用，不入库）：另建一个目录放 `inputs/` 和自己的 `cases.json`，用包装脚本 `var BAE_07_ROOT = "<目录>"; $.evalFile("<仓库>/crates/bae-effects/tests/ae/render_cases.jsx");` 交给 `aectl run`，再 `BAE_07_ROOT=<目录> cargo run -p bae-effects --example ae_compare -- compare`。输入图除了 `chart`、`soft` 还有 `step`（竖直硬边）、`line`（1 像素白线）、`lineg`（灰底白线，能看到负旁瓣）、`ramp`（灰阶，下半是半幅）。

注意：`saveFrameToPng` 返回时文件还没写完，要用新的 `File` 对象轮询（同一个对象会缓存 `exists`/`length`）；`app.newProject()` 遇到没保存的工程会弹保存框，脚本先 `close(DO_NOT_SAVE_CHANGES)`。

## 结论（2026-11-24，AE 26.2.1 macOS）

**偏差来自算法，不是 AE 版本或项目设置。** 07 第一次对照（Windows AE 26.0，`docs/test-reports/win5090/effects-ae-compare.txt`）和本机 macOS AE 26.2.1 用同一个脚本渲出来的结果与 BAE 的差逐项相同（到平均差小数点后三位）。两边的项目设置都是 8 bpc、不线性混合、无色彩管理。

按 AE 实测修正后的结果（最大差 / 平均差，8 位色阶）：

| 用例 | 修正前 | 修正后 | 改了什么 |
|---|---|---|---|
| 色调 `tint_*` | 33 / 10.3 | 1 / 0.8 | 亮度权重是 Rec.601（0.299, 0.587, 0.114），不是 Rec.709。最小二乘拟合 AE 输出得 (0.2989, 0.5871, 0.1141)，残差 ≤ 0.55 |
| 三色调 `tritone_default` | 48 / 12.4 | 1 / 0.0 | 同上 |
| 色阶 `levels_gamma` | 13 / 9.1 | 0 / 0 | "剪切以输出黑色 / 白色"默认是"32 bpc 颜色时关闭"，在 8 / 16 bpc 工程里等于开；BAE 原来按 32 bpc 处理。剪切关闭时输入黑色以下按镜像幂延伸（sign·\|t\|^(1/γ)），不是停在输出黑色 |
| 曝光度 `exposure_*` | 9 / 4.3 | 0 / 0 | 非线性工作空间里 AE 用纯幂 2.4 转线性光，不是 sRGB 分段曲线（2.4：最大残差 0.5；2.2：8.6） |
| 快速方框模糊 `box_4`、`box_10_x3` | 187 / 24.9 | 7 / 0.35 | AE 26 "重复边缘像素"默认开（参数默认值读自 AE），内部像素原本就一致；剩下的差在图像四角 |
| 高斯模糊 `gauss_*` | 75 / 31.2 | 41 / 3.7 | 见下 |
| 高斯模糊（旧版） | 49 / 10.7 | 4 / 1.3 | 见下 |
| 亮度和对比度（新版） | 8 / 4.3 | 未改 | 见下 |

所有效果的输出在 8 / 16 bpc 下按 AE 整数缓冲的方式截断到 [0, 1]（`EffectParams.float = false`，声明式插件的 `BAE_FRAME_FLOAT` 标志），32 bpc 保留超出范围的值。

### 高斯模糊（`ADBE Gaussian Blur 2`）

- **在线性光里模糊。** 1 像素白线的冲激响应，在输出值上求和是 255 的 4.7 倍；先按 2.4 次方转回线性再求和正好是 1.01。所以非线性 8 bpc 工程里 AE 也是先转线性光（纯幂 2.4，和曝光度一样）、模糊、再转回。阶跃响应的中点因此偏向暗部（模糊度 10 时偏 2.5 像素）。BAE 把转换折进第一遍读和最后一遍写，不增加通道；线性化工作空间里不转换。
- **σ = 0.288 × 模糊度**（线性光模型下拟合模糊度 2–70 的冲激响应：0.2877 ± 0.002；原来按 lottie / Skottie 用的 0.3）。
- **核在 |x| ≤ 3σ 处截断**（原来是 ceil(3σ)，多一个尾部采样）。σ < 1/3（模糊度 ≤ 1.15）时 AE 不改变画面。
- **剩下的差（已知，不再追）**：AE 的核在 3σ 外有很小的负旁瓣（灰底白线两侧比背景暗 1 级），更远处（约 7–10σ）有 1–4 级的正旁瓣，像递归 / IIR 高斯近似的下冲。效果是暗通道紧挨强亮边时 AE 被压到 0，BAE 是十几到几十级；只出现在孤立像素上，整幅平均差 1.2–3.7 级。此外 AE 开"重复边缘像素"时图像最外一圈的 alpha 仍会降一点（模糊度 2 时 217，10 时 249），BAE 保持 255。
- 大半径（σ ≥ 6）BAE 用降采样金字塔，在线性光下与精确卷积的差 ≤ 4/255（HDR 亮点旁），0–1 范围的边缘 < 1/255。

### 高斯模糊（旧版，`ADBE Gaussian Blur`）

不做线性化，核是普通高斯，但 σ 和模糊度不成正比（模糊度 1 → 0.80，10 → 4.47，50 → 19.4，70 → 25.9）。BAE 按实测表插值（`LEGACY_SIGMA`，超出表按最后的斜率外推），冲激响应最大差 ≤ 4、多数 ≤ 2。

### 亮度和对比度（新版）

曲线和画面内容无关，先亮度后对比度（复合后误差 1），对比度以 128 为不动点，亮度在暗部是斜率 2^(亮度/110.6) 的直线、到输出约 144 处滚降到 255；负亮度大致是正亮度的反函数（顶端不成立）。幂函数、有理函数、二次贝塞尔的滚降模型最大误差都在 5 级以上，没有找到闭式解。可行的做法是在 AE 里按参数网格采样曲线（亮度 −150…150、对比度 −50…100，步长 10，共 47 条 × 256 项），参数方向线性插值的误差：亮度 ≤ 1.5、对比度 ≤ 0.5。表放在声明式着色器的常量数组里，有的后端（SPIR-V）在运行时索引时会整表复制，所以要改成 Rust 效果 + 曲线纹理，放在下一个 PR。
