# Windows 实机验证 PR #75（Vello 软件适配器降级）

- 日期：2026-11-21
- 测点提交：`7e689db481dd732d4ef0bd92ac010a3a6ec179be`（`origin/render/vector-cpu` / PR #75，与任务指定一致）
- 机器：Windows 11 + RTX 5090 D v2（真显卡）+ Microsoft Basic Render Driver（WARP）
- 约束：只测试；`--locked` 可用；旁路未改业务代码
- 相关：本机 PATH 优先 Obsidian `dxcompiler.dll`（见基线报告 #77）

## 结论（三步）

| 步骤 | 结果 |
|---|---|
| 1. 真显卡 `-p bae-vector -p bae-text` | **默认 DX12/DXC：崩**（`bae-text --test cpu` → 0xc000001d）。**`WGPU_DX12_COMPILER=fxc`：全部通过**（含 CPU↔Vello 逐像素断言 mean &lt; 1%） |
| 2. `BAE_GPU_ADAPTER=software` | **默认与 fxc 均通过、不崩溃**；Vello GPU 用例打印 `skipping Vello GPU test on software adapter "Microsoft Basic Render Driver"`；CPU 后端照常跑。合计约 **67 passed / 0 failed / 1 ignored**（`vello_gpu_stages` ignored） |
| 3. 强制 Vello GPU on WARP（`--ignored vello_gpu_stages`） | **预期崩溃，已采集**：见下 stage 表 |

**PR #75 的降级路径在 WARP 上有效（步骤 2）。** 步骤 3 证实 WARP 上硬跑 Vello GPU 仍会崩；崩溃阶段依赖 DX12 着色器编译器。

## 步骤 1：真显卡

```
git checkout --detach 7e689db
cargo test --locked -p bae-vector -p bae-text
```

| 模式 | 退出码 | 说明 |
|---|---|---|
| 默认（不设 `WGPU_DX12_COMPILER`） | 0xc000001d | 崩在 `bae-text --test cpu`（与基线 DXC 问题同类） |
| `WGPU_DX12_COMPILER=fxc` | 0 | 全绿 |

### CPU ↔ Vello 差值（fxc，真显卡）

`tests/cpu.rs` 中 `cpu_backend_matches_vello_on_hardware_adapters` / text 侧对应用例：

- 断言：`mean < 0.01`（&lt; 1%），且 `&gt;0.1` 的 texel 占比 &lt; 1%
- **测试代码未 `eprintln` 数值 mean**；本机观测为 **assert 通过**（ok），故差值满足 &lt; 1% 门槛
- text 侧另有 ICU 提示：`ICU4X data error: No segmentation model for complex script: Chinese/Japanese`（用例仍 ok）

## 步骤 2：强制 WARP

```
set BAE_GPU_ADAPTER=software
cargo test --locked -p bae-vector -p bae-text
```

| 模式 | 退出码 | 跳过 / CPU |
|---|---|---|
| 默认 | 0 | 多处 `skipping Vello GPU test on software adapter "Microsoft Basic Render Driver"`；`skipping the Vello comparison on a software adapter`；`software_adapters_use_the_cpu_backend ... ok` |
| fxc | 0 | 同上 |

`bae-vector --test cpu`：`4 passed; 0 failed; 1 ignored`（ignored = `vello_gpu_stages`）。  
`bae-vector --test gpu`：7 个用例均 ok（内部跳过真正的 Vello GPU 路径后走兼容逻辑）。

## 步骤 3：根因诊断 `vello_gpu_stages`

```
set BAE_GPU_ADAPTER=software
cargo test --locked -p bae-vector --test cpu -- --ignored --nocapture vello_gpu_stages
```

适配器行（各次一致）：

```
[vello-diag] adapter "Microsoft Basic Render Driver" (Cpu, Dx12, driver "10.0.26100.6725" "")
[vello-diag] stage 1: creating Vello pipelines
```

| `BAE_GPU_VALIDATION` | `WGPU_DX12_COMPILER` | 最后打印的 stage | 退出码 | 备注 |
|---|---|---|---|---|
| 1 | （默认/DXC） | **stage 1** | **0xc000001d** | 无 D3D12 debug / `cannot unwind` 原文 |
| 0 | （默认/DXC） | **stage 1** | **0xc000001d** | 与 VAL=1 相同 → 非单靠校验层 |
| 1 | fxc | **stage 2**（已过 stage 1） | **0xc0000005** ACCESS_VIOLATION | 管线创建成功，空场景 render 时崩 |
| 0 | fxc | **stage 2** | **0xc0000005** | 同上 |

解读（只记录）：

- **stage 1** = 创建 Vello 管线（WARP/DXC 着色器编译路径）→ 默认 DXC 在此 abort
- **stage 2/3** = dispatch：fxc 能建管线，但 WARP 在 **stage 2 空场景渲染** 仍 access violation
- 故 PR #75 在软件适配器上改走 `vello_cpu`、并 skip Vello GPU，与本机证据一致

## 与基线 #77 的交叉

真显卡默认 DX12 失败主要来自 PATH 上第三方 DXC；**与 WARP 上 Vello GPU 崩溃是不同问题**。PR #75 解决的是后者（软件适配器降级）；前者需环境/DXC 治理（fxc 或合格 DXC）。
