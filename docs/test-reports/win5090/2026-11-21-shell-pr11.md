## 追加：图层改名四路 A/B（2026-11-21 续）

- 测点：同机 BAE @ `origin/dev` **`97cc290`**（`WGPU_DX12_COMPILER=fxc`）；持 `gui.lock`

- 代码侧：`timeline.rs` 改名只认 `lost_focus` / `Escape`（取消）；**没有** Project 面板那种显式 `Key::Enter` 提交；每帧 `request_focus()`

**提交（让新名落盘）**：自动化下 `Return` / `Enter` / Tab / 点击查看器（orca 与 SendInput）均**未能**退出编辑态（`Escape` 会取消并丢弃缓冲）。因此本轮只能证明「编辑框是否吃到字符」，不能证明 attr.set 落库。疑点：时间轴缺 Enter 提交 + 每帧 `request_focus()`，与 Project 面板行为不一致；需产品侧或人工鼠标点开确认。

**对原 #86 结论的修正**：先前「中文 paste 不保留」主因是 **`orca computer paste-text` 进不了 egui `TextEdit`**（英/中一样失败），不是中文编码问题。`type-text` 与原生 Ctrl+V 对中英文都进框。

## 问题列表

1. **`orca paste-text` 无法写入时间轴改名框**（英/中相同）；原生剪贴板 Ctrl+V 可以——自动化应用 Ctrl+V 或 `type-text`，勿依赖 `paste-text`。
2. **时间轴改名提交**：自动化无法触发 `lost_focus` 提交；建议与 Project 面板对齐加 `Key::Enter`，并复核每帧 `request_focus()`。人工鼠标点开仍建议验一次。
3. 系统 IME 组字上屏未测。
4. （观察）多显示器移动后 list-windows 的 `x` 为 a11y/缩放坐标，与 Win32 物理坐标不同，写自动化时需统一坐标系（与 #3 相同）。
