# Windows 实机体积测量（#7）

- 日期：2026-11-21
- 测点：`origin/dev` @ **`3fb7b6df4c88553a5fad6ebf91962c15b0b3631b`**（短哈希 `3fb7b6d`，含已合并的 #64 motion panels）
- 机器：Windows 11 x64 / MSVC，`cargo build --release -p bae`
- 对照：macOS 报告约 **22.11 MiB**；本机 `bae.exe` **29.04 MiB**（30,452,736 B），多约 **6.93 MiB**

## 结论摘要

| 项 | 结果 |
|---|---|
| `bae.exe` | **29.04 MiB**（30452736 B） |
| vs macOS 22.11 MiB | **+≈6.9 MiB** |
| `.text`（cargo-bloat） | **22.0 MiB**（占文件 75.8%） |
| 最大 crate | `std` 3.9 MiB → `loro_internal` 1.9 → `naga` 1.1 → `bae_model` 0.96 → `egui` 0.80 → `wgpu_core` 0.74 |
| 重复依赖 | 多版本：`skrifa` 0.44/0.49、`harfrust` 0.12/0.15、`read-fonts` 0.41/0.46、`windows-sys` 0.52/0.61、`hashbrown` 0.16/0.17、`thiserror` 1/2、`getrandom` 0.2/0.3/0.4 等 |
| Windows 独有倾向 | `windows` / `windows-sys` / `windows-core` 族、`wgpu-core-deps-windows-linux-android`、`windows_x86_64_msvc`（macOS 无此栈；Metal 侧另有 objc 等，不在本二进制） |

**归因（为何 Windows 更大）：**

1. **MSVC `std` 偏大**：bloat 里 `std` 独占 **3.9 MiB**（.text 17.9%），是单 crate 最大块；与 Apple 平台标准库体量差异是跨平台常见落差。
2. **Win32/DX12 绑定**：`windows` v0.62 + `windows-sys`（两版本）+ `wgpu-hal`/`wgpu-core-deps-windows-linux-android` 只在 Windows 链接进本二进制（macOS 走 Metal，不带这套）。
3. **字体栈双份（跨平台，两边都有，但在 Win 体积里可见）**：egui/epaint 仍用 `skrifa 0.44` + `harfrust 0.12`，vello/parley 用 `skrifa 0.49` + `harfrust 0.15` + `read-fonts` 双版本——bloat 中 skrifa+harfrust+read_fonts 合计已超 **1.8 MiB** 量级。
4. **其余重复版本**（`hashbrown`/`thiserror`/`getrandom`/`syn` 等）单个不大，但抬高链接与元数据；不是 +7 MiB 的主因。

无法把 +6.9 MiB 精确拆成「纯 Windows 独有」字节；量级上 **std 差 + windows 绑定 + 双字体栈** 已足够解释大部分差额。
