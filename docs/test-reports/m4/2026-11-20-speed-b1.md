# macOS 实机：AE vs BAE 速度对比（B1，Apple M4）

- 日期：2026-11-20
- 机器：MacBook（Apple M4，16 GB），macOS 26.7.3
- BAE：`origin/dev` @ `5337211`（含 #94 导出流水线），release 构建
- AE：After Effects 2026 `26.2.1`（英文界面）
- 测量期间关闭了其他编译任务，负载 load average < 2。

## 场景：和 BAE 完全一致的 B1

B1 = 1920×1080、30 fps、10 秒（300 帧），61 个图层：50 个带动画的纯色层（位置 3 个关键帧、旋转、缩放、不透明度；每第 5 个用相加/滤色/相乘/叠加）、10 个素材 PNG 标签层、1 个背景层，没有模糊和发光（定义见 `crates/bae-render/src/fixture.rs` 的 `b1`）。

和 5090 上的 #90 不同，这次 **AE 工程是从 BAE 工程直接转出来的**，两边的场景逐值一致（同一组随机值、同一批关键帧、同一批 PNG 素材）：

1. `cargo run --release -p bae-render --example b1_project -- <dir>` 生成 `B1.bae`；
2. `bae export-json B1.bae --compact -o b1.json`；
3. [`scripts/build_b1.jsx`](scripts/build_b1.jsx) 在 AE 里读这份 JSON，逐层重建（纯色的颜色和尺寸、导入同一批 PNG、所有关键帧改为线性插值，包括空间插值、混合模式），保存成 `B1.aep`。

## 测法

- 每项 300 帧和 1 帧各跑 3 次，取中位数。用 1 帧的耗时近似固定开销。
- **BAE**：`bae render B1.bae --comp b1 --depth 8 --resolution full -f tiff --compression none`（或 `-f png`，默认压缩级别 fast）`--frames all`，墙钟时间包括进程启动和 GPU 初始化。驱动脚本：[`scripts/bench.py`](scripts/bench.py)。
- **AE**：
  - **TIFF**：渲染队列，渲染设置 `Best Settings`，输出模块 `TIFF Sequence with Alpha`（RGB + Alpha，8 bpc，不压缩），只给 `renderQueue.render()` 计时，**不包括启动 AE**（AE 已经运行；热启动约 2 秒，冷启动 5~12 秒）。
  - **PNG**：AE 2026 的输出模块格式在脚本里是只读的，也没有 PNG 模板（和 5090 上一样），所以照 #90 用 `comp.saveFrameToPng` 逐帧写，等 300 个文件都写完才停表。这不是渲染队列的路径，只作参考。
  - 每次计时前用 `app.purge(PurgeTarget.ALL_CACHES)` 清掉内存和磁盘缓存。**不清缓存时**，AE 的第 2、3 次会复用缓存里已经渲好的帧（TIFF 300 帧从 6.6 秒降到 3.5 秒），对 BAE 不公平；BAE 每次都是新进程，没有持久缓存。
  - 打开工程另计，约 0.086 秒。
  - 脚本：[`scripts/ae_time.jsx`](scripts/ae_time.jsx)，[`scripts/ae_bench.sh`](scripts/ae_bench.sh)（通过 `tools/ae/aectl` 运行）。
- **aerender 在这台 Mac 上用不了**：独立启动的 `aerendercore` 卡在 Adobe 授权库的初始化里（`aelicensing::DoSetup → … → DataStorageFs::GetInstance → std::mutex::lock`，CPU 占用为 0，10 分钟没有输出一帧），是这台机器的授权环境问题。我们没有去碰授权，改用已经运行的 AE 里的渲染队列。

## 结果

| 侧 | 方法 | 300 帧，3 次（秒） | **中位数（秒）** | 1 帧中位数（秒） | 每帧增量（毫秒） |
|---|---|---|---:|---:|---:|
| AE | 渲染队列 TIFF（清缓存，不含启动） | 5.493 / 5.757 / 6.074 | **5.757** | 0.105 | 18.9 |
| AE | `saveFrameToPng` PNG（清缓存） | 23.048 / 23.244 / 23.330 | **23.244** | 0.060 | 77.5 |
| BAE | `bae render` TIFF（不压缩，含进程启动） | 1.537 / 1.255 / 1.429 | **1.429** | 0.031 | 4.7 |
| BAE | `bae render` PNG（含进程启动） | 0.464 / 0.459 / 0.459 | **0.459** | 0.031 | 1.4 |

每帧增量 = (300 帧耗时 − 1 帧耗时) / 299。

- **同格式不压缩 TIFF：BAE 比 AE 快约 4.0 倍**（5.757 / 1.429）。这还是偏向 AE 的算法：AE 不算启动，BAE 算上了进程启动和 GPU 初始化（共约 0.03 秒）。BAE 这里主要卡在写盘：300 帧共 2.5 GB，`--json` 显示编码线程大部分时间在等磁盘（`encoder_stall_ms` 879），GPU 渲染加回读每帧不到 2 毫秒。
- **PNG：BAE 0.459 秒**，比 AE 能用的脚本写 PNG 方式快约 50 倍；但两边路径不同（AE 不是渲染队列），只作参考。
- **固定开销**：BAE 整个进程（启动、GPU 初始化、读工程、出 1 帧）约 0.03 秒；AE 不含启动时，打开工程约 0.09 秒，1 帧渲染约 0.1 秒。

BAE 各阶段（300 帧，`--json` 最后一次）：

| 阶段 | TIFF | PNG |
|---|---:|---:|
| 总墙钟 `total_ms` | 1378.6 | 434.9 |
| 求值 `eval_ms`（累计） | 43.4 | 57.6 |
| GPU 渲染 `render_ms`（累计） | 157.8 | 178.5 |
| 回读等待 + 拷贝 | 374.8 | 381.4 |
| 编码 `encode_ms`（多线程累计） | 196.6 | 1590.1 |
| 编码等待写盘 `encoder_stall_ms` | 878.9 | 1.1 |

原始数据：[`speed-b1-bae.json`](speed-b1-bae.json)（BAE，每次的帧明细只保留前两帧），[`speed-b1-ae.txt`](speed-b1-ae.txt)（AE：`模式 帧数 第几次 渲染毫秒,打开工程毫秒`）。

## 和 5090（#90）的关系

#90 是在 #94 之前测的，当时 `bae render` 同步回读、单线程写 PNG，只快 1.4 倍。#94 把回读改成流水线、编码改成并行之后，M4 上 B1 导出 PNG 从 5.03 秒降到 0.47 秒（10.7 倍）。5090 上的重测见 #97：PNG BAE 2.008 s / AE aerender 22.017 s（约 11 倍），不压缩 TIFF BAE 2.006 s / AE 18.515 s（约 9 倍）；那边的 AE 计时包含启动 AE。
