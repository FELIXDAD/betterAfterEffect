# BAE 0.0.1 发布说明

> 日期：2026-11-22。分支：`dev` → `main`，标签 `v0.0.1`。

BAE（betterAfterEffect）的第一个可运行版本：一个以 GPU 为基础的 AE 式动画软件。0.0.1 打通了最小的完整流程：**打开应用 → 新建合成 → 加图层 → 打关键帧 → 预览 → 通过渲染队列导出 → 保存和重新打开工程**。发布前又做了一轮 AE 对齐：菜单栏和快捷键按 AE 26 生成，加上了工具栏和查看器里的绘制工具、AE 的各种设置对话框、首选项、图表编辑器和蒙版渲染，目标是让 AE 用户上手时感觉不到差别。同时，数据模型、动画求值、GPU 合成、色彩、媒体、协同、Agent（MCP）、插件、AE/Ai 互转这些底层模块都已经有了第一版。

这是技术预览，不适合用于正式生产。

## 支持的平台

- macOS 12 及以上，Apple Silicon（主要开发和测试平台）。
- Windows 10 21H2 及以上 / Windows 11，x64，D3D12。在 RTX 5090 实机上完成了验收（`docs/test-reports/win5090/`）。
- CI 在每个 PR 上检查 macOS arm64 和 Windows x64：格式、clippy、全部测试、单一 wgpu、release 体积、无界面冒烟测试、打包。

## 安装和首次打开

两个平台的包都没有正式签名（见"已知限制"），所以第一次打开要手动放行一次：

- **macOS**：解压 `BAE-0.0.1-aarch64-macos.zip`，把 `BAE.app` 拖到“应用程序”。因为应用没有经过公证，第一次打开时 macOS 会提示无法验证开发者：在访达里右键点 `BAE.app`，选“打开”，再在弹出的对话框里点“打开”。如果没有“打开”按钮（较新的 macOS），先关掉提示，然后到“系统设置 ▸ 隐私与安全性”，在“安全性”一节里找到 BAE，点“仍要打开”并确认。只需要这样操作一次，之后可以正常双击打开。
- **Windows**：解压 `BAE-0.0.1-x86_64-windows.zip`，双击 `bae.exe`。如果出现“Windows 已保护你的电脑”（SmartScreen），点“更多信息”，再点“仍要运行”（#217）。

## 快速开始

```sh
cargo run --release -p bae                        # 打开应用
cargo run --release -p bae -- <工程.bae|.baez>     # 启动时打开工程
bae render <工程> --comp <合成> --frames all -f png -o out/name_####.png --json
bae export-json <工程>                            # 工程导出成可读 JSON
bae mcp [工程]                                    # 给 Agent 用的 MCP 服务器（stdio）
bae plugin list | check <插件>                    # 插件
bae gpu-info                                      # 显卡信息
```

## 0.0.1 能做什么

### 在应用里做动画（AE 式动效工作区）

- **外壳**：AE 式的停靠面板、标题栏、深色主题、矢量图标、工作区切换（首次启动选岗位）、中英文界面（中文用语和 AE 官方中文一致，比如单位写“像素”）、历史面板、Agent 活动与提案面板。界面用系统字体；中文输入法候选框跟随光标。
- **项目面板**：文件夹、合成、素材、纯色；搜索；新建、删除、重命名；拖到时间轴或查看器生成图层。
- **合成查看器**：在 GPU 合成器上实时显示当前帧；选取、移动、边界框、手柄、锚点；缩放、平移、分辨率、透明网格、安全框。
- **时间轴**：当前时间指示器、工作区域、开关列、父级与关联器、图层条移动和修剪、属性树、秒表和关键帧导航、关键帧选择 / 框选 / 拖动 / 复制粘贴、F9 缓动、表达式。
- **属性面板**、**预览**（播放、逐帧、循环、播放工作区域）。
- **工程文件**：新建、打开（`.bae` 目录或 `.baez` 单文件）、关闭、保存、另存为，原生对话框，关闭前提示保存。
- **渲染队列**：「合成 ▸ 添加到渲染队列」（Cmd/Ctrl+M），输出 PNG / TIFF / OpenEXR 序列，后台渲染、不卡界面，进度显示，可以停止。

### AE 对齐（发布前的一轮）

照着 AE 26 实测的数据做（菜单、快捷键、对话框、首选项和各个工具的交互都先在 AE 26.2.1 里记录下来，放在 `docs/spec/ae/`），AE 用户熟悉的操作在 BAE 里应该一样。

- **菜单栏和快捷键**：从 AE 26 的命令目录生成，菜单结构、菜单项名称（中英文）和默认快捷键和 AE 26 一致（#160、#172）。AE 26 的全部默认快捷键都已登记；图层开关、3D 图层、品质和标签颜色可以从 AE 的菜单和快捷键操作（#182、#186）。
- **工具栏和查看器工具**：选取、抓手、缩放、旋转、向后平移（锚点）、形状（矩形、圆角矩形、椭圆、多边形、星形）、钢笔（添加 / 删除 / 转换顶点、RotoBezier）、横排文字；工具的弹出组和 AE 的工具快捷键，按住临时切换工具；吸附、框选、方向键微移、蒙版顶点编辑。形状工具在查看器里直接画出形状图层或蒙版；文字工具支持点文字和段落文字、输入法、编辑已有文字（#181）。
- **对话框**：合成设置（Cmd/Ctrl+N、Cmd/Ctrl+K，含 AE 的预设）、纯色设置（Cmd/Ctrl+Y、Cmd/Ctrl+Shift+Y）、摄像机设置、灯光设置、预合成（Cmd/Ctrl+Shift+C）、导入（Cmd/Ctrl+I，也可以把文件拖到项目面板）、关键帧插值和关键帧速度、AE 式拾色器（#166、#167、#174、#181）。
- **首选项**：按 AE 26 的 16 页排布，设置会作用到撤销次数、标签颜色、外观、网格、自动保存，以及新建图层、合成和导入的默认值（#161、#188、#198）。
- **图表编辑器**：值图表和速度图表，拖动关键帧和手柄，单独尺寸（#165）。关键帧拖动时按 Shift 吸附、按 Alt 缩放，关键帧右键菜单（#174）。
- **蒙版渲染**：GPU 上的图层蒙版，支持各种模式、反转、不透明度、扩展和 X / Y 分开的羽化（#164）。

### 验收中发现、发布前已修复

- **#100 保存顺序**：输入数值后马上保存，刚输入的值也会存进去；补了关键帧保存往返的回归测试。
- **#102 按键路由**：键盘焦点所在的控件先拿到它要用的键。在文本框里输入空格不会开始播放；焦点在按钮上时，空格和 Enter 会按下按钮；其他情况才当作快捷键。
- **#103 渲染队列**：输出路径带空格时，"在资源管理器中显示"也能定位到文件；Enter 不会被处理两次（焦点在"停止"上按 Enter 不会再触发项目面板改名）；停止后保留已经渲出的完整帧。
- **#99 `tools/ae/aectl`**：osascript 在脚本运行前就失败时立刻报错（退出码 5），不再等到超时；AE 不响应 Apple 事件时按超时处理，并重启 AE。
- **macOS 验收发现的问题**（#121、#122、#123、#127、#129、#130、#139、#144）：下载后的 `BAE.app` 签名有效（#120）；应用图标、`.bae` / `.baez` 文档类型，可以在访达里双击打开；重新打开工程时恢复之前打开的合成；时间轴改名（Enter 开始改名、全选原名）、Shift+单击选连续范围；复制 / 拆分图层后选中新图层；同一帧里连续新建不会重名；欢迎框打开时快捷键不作用到后面的工程；锁定的图层在每个修改里都不能被选中或编辑；渲染队列的空路径、扩展名和帧范围检查；打开损坏或不存在的工程时，各个入口的错误提示一致且写明文件名；另存为到已有的 `.bae` 工程会先确认再替换（macOS 和 Windows，#139、#148）；控件都有无障碍标签，同类控件的标签带上属性名或图层名。
- **界面**（#138、#141、#149、#153、#201）：没有缺字方块，所有命令、面板和默认名称都有中文；高 DPI 和窄面板下布局不裁切；改用系统字体（Windows 可执行文件小 1.35 MiB）；中文界面的单位写“像素”。
- **最终回归发现**：图层剪切 / 复制 / 粘贴，可以跨合成粘贴（#210）；所有对话框里按 Enter 等于“确定”（#209）；首选项里纯色文件夹的默认名跟随界面语言（#212）；`####` 输出只渲一帧时也带帧号，和 AE 一样（#211）；Windows 上渲染队列默认输出到“视频”文件夹（#219）；关闭项目后合成和时间轴面板的标签不再显示旧合成名（#221）；Windows 上 Ctrl+Shift / Ctrl+Alt + C / X / V 执行各自的快捷键（#224）；Windows 原生菜单里带 & 的菜单名（比如 Effects & Presets）正常显示（#229，修复 #226）。
- **Windows 稳定性**（#173、#195）：GPU 设备创建串行化，修掉了 CI 上偶发的访问违规（#154）；给 wgpu-hal 打补丁，FXC 编出的着色器不再跨线程共享，修掉一个可能导致堆损坏的崩溃（#194）。

## 性能

### B1 导出：AE vs BAE（同机对比）

B1 = 1080p30、300 帧、61 层（50 个带动画的纯色、10 个素材 PNG、1 个背景，含相加 / 滤色 / 相乘 / 叠加）。每项 3 次取中位数，墙钟时间。

| 平台 | 输出 | AE | BAE 0.0.1 | 倍数 |
|---|---|---:|---:|---:|
| Windows，RTX 5090 D（[#97](../test-reports/win5090/2026-11-21-final-acceptance-001.md)） | 不压缩 TIFF | 18.515 s（aerender，含启动 AE；每次清缓存后 18.957 s） | **2.006 s** | **约 9×** |
| Windows，RTX 5090 D | PNG | 22.017 s（`saveFrameToPng`，未清缓存）/ 28.799 s（每次清缓存） | **2.008 s** | **11–14×** |
| macOS，Apple M4（[报告](../test-reports/m4/2026-11-20-speed-b1.md)） | 不压缩 TIFF | 5.757 s（应用内渲染队列，清缓存，**不含**启动 AE） | **1.429 s** | **约 4.0×** |
| macOS，Apple M4 | PNG | 23.244 s（`saveFrameToPng`，AE 没有 PNG 输出模板） | **0.459 s** | 约 50×（AE 走的不是渲染队列，仅作参考） |

**稳妥的数字看 TIFF 对 TIFF：Windows 上约 9 倍**，AE 的缓存对它基本没有影响。

只渲 1 帧的固定开销：Windows 上 BAE 约 0.96 s、AE（aerender）约 7.9 s（都含启动和加载工程，见 [#90](../test-reports/win5090/2026-11-21-speed-b1.md) 第 4 节）；macOS 上 BAE 整个进程约 0.03 s，AE 不含启动时，打开工程约 0.09 s、出 1 帧约 0.1 s。

说明：

- **两个平台的 AE 测法不同**。Windows 上 TIFF 用 aerender，计时包含启动 AE；PNG 用 `comp.saveFrameToPng` 逐帧写（中文版 AE 的输出模块格式在脚本里改不了，也没有 PNG 输出模板），计时包含打开工程。macOS 上独立的 aerender 卡在 Adobe 授权初始化里（这台机器的授权环境问题），所以改用已经运行的 AE 里的渲染队列，计时不含启动，对 AE 更有利。
- **Windows 上 AE 的磁盘缓存是开着的**。原来的三次计时没有清缓存；之后每次计时前清空缓存重跑：TIFF 基本不变（中位 18.515 s → 18.957 s），PNG 慢了 31%（22.017 s → 28.799 s）。所以 PNG 写成 11–14 倍：11 倍是 AE 可能复用缓存时的数字，清缓存后约 14 倍。
- macOS 上 AE 工程是从 BAE 工程直接转换的，两边场景逐值一致；每次计时前清掉 AE 的内存和磁盘缓存（不清的话，AE 第 2、3 次会复用缓存里的帧）。
- BAE 的瓶颈在编码和写盘：M4 上 TIFF 300 帧共 2.5 GB，编码线程大部分时间在等磁盘；GPU 渲染加回读每帧不到 2 毫秒。
- #94 的导出流水线（异步回读、并行编码）之前，BAE 自己慢得多：M4 上 B1 导出 PNG 从 5.03 s 降到 0.47 s（10.7 倍）；5090 上从 13.010 s（#90）降到 2.008 s（约 6.5 倍）。#94 之前在 5090 上对 AE 只快 1.4 倍。

### 其他

- 工程模型：1 万个 Prim 打开 111 ms，一次修改到发出事件约 5 µs。
- 求值：1000 个图层单帧 0.36 ms；100 层 × 2 个表达式单帧 1.07 ms。
- 媒体：4K ProRes 拖动播放头跳帧 ~40 ms → ~9 ms；导出 4K ProRes 23 → 60+ fps（macOS）。

## 体积

release 可执行文件（strip 后）：**macOS 23.31 MiB（`BAE.app` 23.26 MiB），Windows `bae.exe` 31.07 MiB**（dev `6911155` 的 CI 实测；安装包 zip：macOS 10.76 MiB，Windows 12.20 MiB）（32 MiB 是临时预算，从 30 MiB 放宽而来（#180），等 0.0.1 之后改成 `panic = "abort"`，Windows 会回到 30 MiB 以内；解压后应用包 40 MiB、压缩后安装包 20 MiB 的上限不变）。0.0.1 前做过一次体积清理（#89）：统一成一套字体栈、冷路径 crate 用 `opt-level = "s"`；热路径（求值、渲染、解码）保持 `opt-level 3`。

## 已知限制

- macOS 包只有 ad-hoc 签名，没有用 Apple Developer ID 签名，也没有经过公证。正式的签名和公证需要苹果开发者账号，放到 0.0.1 之后。
- Windows 的 `bae.exe` 没有代码签名，第一次运行时 Windows SmartScreen 会提示。
- **Windows 视频编解码只是占位**：Windows 上只支持图片和图片序列，影片的解码和编码在 0.0.1 之后由 08 做（Media Foundation）。
- Windows DX12 固定用 FXC 编译着色器（避免加载 PATH 上不兼容的 dxcompiler.dll）；随应用发布 DXC 以后再评估。
- 没有显卡（软件适配器 WARP / llvmpipe）时，矢量和文字退回 vello_cpu 渲染，速度较慢。
- **效果菜单整体是灰的**：效果库（7 个颜色校正和两种模糊）已经合并，但还没接进界面，下个版本接入。
- `bae render --comp` 还不认界面上显示的合成名（比如带空格的名字会报 invalid prim name），要用合成的内部名（#214）。
- PNG 默认输出带 alpha（透明背景），AE 默认的 PNG 输出模块是 RGB（#225）。
- 文本框里用拼音组字上屏后按 Ctrl+Z，会退回到组字的中间文本（比如 `w'q'g't`），而不是上屏前的内容（#222）。
- Windows 的 `bae.exe` 没有版本资源，文件属性里看不到版本号（#217）。
- 部分快捷键可能被其他程序注册的全局热键占用，这时按键到不了 BAE，属于系统环境问题。
- Windows 上 BAE 运行时把显示缩放调小，菜单栏下方可能留下一行旧文字的残影，重启 BAE 即可（#227）。
- 渲染队列面板的内容贴着面板边缘，缺少内边距（#228）。
- 关闭项目后，渲染队列里的旧项不会清除；打开别的工程后再渲染这一项会失败，手动把它从队列里移除即可，下个版本修（#231）。
- 分镜（13）和剪辑（14）工作区 0.0.1 没有，只有规划。
- AE 互转：只有 AE 导出脚本和交换格式；BAE 侧的导入器、导回 AE 的 .jsx、Lottie、直接读 .aep 都还没做。
- AE 功能清单（`docs/spec/ae/`）还缺几章，部分草稿未核对。
- 渲染队列面板只提供 PNG / TIFF / OpenEXR；macOS 上的 H.264 / ProRes 目前只能用 `bae render --format`。
- Windows 可执行文件 31.07 MiB，超过原来 30 MiB 的预算，0.0.1 临时放宽到 32 MiB；0.0.1 之后改成 `panic = "abort"`（Windows 约小 7 MiB）再收回。
- `panic = "abort"` 推迟到 0.0.1 之后：现在崩溃时的紧急保存靠捕获 panic，要先换掉这套机制。
- 系统输入法的真实拼音组字没有端到端的自动测试（自动化环境没有辅助功能权限，发不了系统按键）。macOS 验收在 egui 层注入和真实输入法相同的组字事件，验证了上屏结果和组字时快捷键不会误触发；候选框跟随光标由单元测试覆盖。
- 渲染队列停止后，不会像 AE 那样给剩下的帧生成一个新的队列项（已经渲出的帧会保留），0.0.1 之后做。
- CI 的 macOS 虚拟机里，H.264 编码测试偶尔因 SIGABRT 失败；真机上没有这个问题，0.0.1 之后查。
- **合成和图层标记**（标记命令、时间轴上的标记、标记对话框）没赶上 0.0.1，下个版本加入（#185）。
- **彩色 emoji**：界面里的彩色 emoji（比如图层名里的 😀）显示为方块，名字数据本身不受影响，导出和保存都保留原样。
- **从右往左书写的文字**：阿拉伯文、希伯来文等需要从右往左排、字母连写的文字，界面暂时显示不正确（字母顺序和连写形式不对），名字数据本身不受影响。0.0.1 不处理。
- **中文 Windows 上 Alt+Shift+P（设置位置关键帧）可能没反应**：Alt+Shift 是切换输入法的系统热键，按键会被系统截走，AE 也有同样的冲突。绕开的办法：点属性旁的秒表或关键帧导航器的 ◆；或者先切到英文输入法；或者在 Windows 设置里改掉输入法的切换热键。

## 验收方式

所有测试都由 agent 完成，发布的是两边验收都通过的版本。

- **macOS（Apple M4）**：独立的验收 agent 按清单测试主流程和边界情况，测试写成回归测试，随 #119 合入（`apps/bae/src/acceptance/`，在没有窗口的 shell 里注入真实的键盘、鼠标和输入法事件；`apps/bae/tests/acceptance_cli.rs` 测真实的可执行文件），报告见 [m4/2026-11-21-acceptance-0.0.1.md](../test-reports/m4/2026-11-21-acceptance-0.0.1.md)。第一轮发现的问题（#105 到 #116 等）都已修复，并由验收 agent 复测后关闭。
- **Windows（RTX 5090 D）**：最终验收（#97）之后，每个修复都在 5090 上复测（高 DPI #147、中文界面和缺字 #151 等）；AE 对齐这一轮合入后又做了最终回归：Windows 第 1–5 批全部通过（缩减版：只测 Windows 特有风险，共用逻辑以 macOS 回归为准，报告 #218）。

## 怎么做出来的

0.0.1 由 21 个工作流并行开发：每个工作流一个分支和一个 Agent，按 `docs/WORKSTREAMS.md` 的依赖顺序推进；所有修改通过 PR 合并到 `dev`，由协调会话审查；CI 和 Windows 实机验收把关。
