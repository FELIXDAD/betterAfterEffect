# 产品愿景与需求

## 一句话

做一个更好、更轻的 AE 类动画制作软件：以 GPU 运算为基础，轻量、跨平台，支持多人实时协作和 Agent 操作，并打通 Illustrator 与 After Effects，让分镜、动效（以及剪辑）在同一个平台、同一个工程里工作。

这不只是"加速版 AE"。和 AE 相比，核心差异有三点：

1. **一个工程容纳多个岗位。** 分镜、动效、剪辑在同一个工程里完成，不再在 Ai → AE → Pr 之间来回导出导入。
2. **工程天生是分层、多人同时编辑的。** 借鉴 USD 的多层叠加思路，每个人改自己的层，所有人实时看到合成后的结果。
3. **Agent 是一等用户。** Agent 和人用同一套命令操作工程，能看到渲染结果，并遵守一套动画操作规范。

内部代号 **BAE**，代码里的 crate 前缀统一用 `bae-`。

## 岗位与工作区

| 岗位 | 原来用什么 | 在 BAE 里做什么 | 工作区 |
|---|---|---|---|
| 分镜 / 设计 | Illustrator（以及 PS、Storyboard Pro） | 画板、矢量绘制、分镜格、镜头说明、动态分镜 | 分镜工作区（Ai 式界面） |
| 动效 | After Effects | 合成、图层、关键帧、表达式、效果 | 动效工作区（AE 式界面） |
| 剪辑 | Premiere / Final Cut | 序列、剪切、节奏、配乐 | 剪辑工作区 |
| 导演 / 审阅 | 看导出的视频 | 播放、批注、版本对比 | 审阅工作区 |
| Agent | — | 通过 MCP 读写工程、生成动画、批处理 | 无界面，或 Agent 面板 |

## 需求（按优先级）

### 1. GPU 运算与性能（最高优先级）

- 渲染、合成、矢量、效果、色彩转换全部在 GPU 上完成。帧从解码到显示尽量不回到 CPU。
- 目标：常见动效工程在 1080p 下能实时预览；最终渲染速度显著快于 AE（用基准工程在同一台机器上实测，目标 5 倍以上）。
- 操作跟手：冷启动 2 秒以内，拖动时间轴不卡。
- 在性能的基础上做好文件格式适配和色彩管理：线性工作流、兼容 ACES 和 OCIO、支持 HDR 显示。

### 2. 多人协同与版本管理

- 多人可以同时打开、编辑同一个工程，实时看到彼此的修改。
- 借鉴 USD 的多层嵌套：工程由多个"工程层"叠加而成。每个岗位、每个人、每个 Agent 默认编辑自己的层，强层的值覆盖弱层；同一层里的并发编辑由 CRDT 自动合并。
- 版本管理：自动历史、命名版本、分支（例如客户修改的 A/B 方案）、差异对比、回滚，能查到谁改了什么。
- NAS 支持：
  - 工程可以直接放在 NAS 共享目录上多人协作，不需要服务器。
  - 也可以在 NAS 上用 Docker 运行协作服务，负责实时同步、素材存储和代理生成。

### 3. 统一制作流程与工作区

- 打通分镜、动效、剪辑。三者通过"镜头（Shot）"关联：分镜格 ↔ 动效合成 ↔ 剪辑片段，任何一端更新，其他端引用到的都是最新内容。
- 按岗位提供不同的工作区，不要求所有人用同一种布局，布局可以自定义并保存。
- 界面高度参考 AE 和 Illustrator，最大限度保留原有使用习惯：
  - 面板布局、交互方式与 AE/Ai 一致。
  - 术语使用 Adobe 官方中文版的译名（合成、图层、关键帧、预合成、画板……）。
  - 快捷键按工作区切换：动效工作区用 AE 键位，分镜工作区用 Ai 键位。
  - 只参考布局与交互习惯。图标和视觉资源自己绘制，不复制 Adobe 的图标、图片等受版权保护的资源。

### 4. 跨平台与工程交接

- 首发 Windows（x64）和 macOS（Apple Silicon 优先，兼容 Intel）。
- Android 和 iOS 以后再做，现在不做；但核心模块不能写死桌面假设（见架构文档）。
- 支持与 AE / Ai 工程互转：能导入 AE 工程和 Ai 文件，也能导回去，交给只用 AE/Ai 的人。

### 5. 轻量化

- 在实现以上目标的同时，把安装包体积压到极限。
- 不打包 Chromium、Qt、FFmpeg、OpenColorIO、OpenUSD 这类大型运行时，优先用系统自带能力（系统视频编解码、系统字体）。
- 体积预算由 CI 强制检查（见架构文档）。

### 6. Agent 接入与操作规范

- 产品设计上就支持 Agent：所有操作都是 Agent 可以调用的命令（通过 MCP 暴露），Agent 能"看到"渲染结果。
- Agent 以协作者身份加入工程，改动默认进入它自己的提案层，人审核后再合并。
- 编写规范的《Agent 动画操作指南》：让 Agent 不只是能连上，还知道怎样正确地做出合格的动画。

### 7. 工程与素材一体化打包

- 参考 Blender 的资源打包：把工程和它用到的所有外部素材打成一个自包含的单文件，方便交接、迁移和归档。接收者不依赖原电脑的素材路径，也不用另外收集资源。
- 可选"视频裁片"：多花一些处理时间，只打包时间线上实际用到的视频片段，不带完整的长原始视频，减小交接文件体积。不开启时保留完整素材。
- 裁片只用于生成交接包，不修改原始素材和原工程。片段前后是否留余量、是否重新编码、变速和嵌套引用如何处理，后续再定（先在接口里留好参数）。
- 不打包时，按行业通行做法引用素材：同时记录相对工程的路径和原始绝对路径，打开时依次查找，找不到再提示重新链接（详见架构文档第 16 节）。

### 8. 预留 AE 插件兼容能力

- AE 用户基础庞大、插件生态丰富，软件要尽量延续 AE 用户熟悉的体验，降低迁移成本。
- 在核心架构设计阶段，就参考 AE 插件（.aex）的开发流程和所需能力，倒推需要预留的接口和适配机制，避免将来因为底层不兼容而大改。
- 现阶段只要求架构上提前考虑兼容，不要求首版就能运行 AE 插件。具体能兼容哪些插件类型、平台和功能，后续再验证（详见架构文档第 15 节）。

### 9. 自有插件体系

- 建立完善的自有插件模块、开发接口和配套文档，让用户和开发者参与功能扩展和生态维护。
- 插件体系是核心设计的一部分，不是产品完成后临时追加。内置功能本身也通过同一套插件接口注册，保证接口够用（详见架构文档第 14 节）。
- 插件是否开源、采用什么许可、具体接口规范，暂未确定。

## 优先级总原则

1. **性能第一。** 以上任何需求如果和性能冲突，先往后放，暂不考虑兼容。如果兼容只会让用到它的那一部分变慢、不影响软件本身，则可以做。
2. **插件体系必须现在就设计好**，不能后补。
3. **当前版本优先做好"更快的 AE"。** 分镜（Ai 式）和剪辑是后续"大一统"的方向，现在只留好接口、写好框架，不强制完成。剪辑的底层逻辑可以统一，界面按操作习惯提供 Premiere、达芬奇、Final Cut Pro 等风格的前端预设。

## 现在不做

- 不做 AE 插件，也不依赖 AE 运行。
- 首版不运行 AE 第三方插件（.aex），但架构上预留兼容层（见第 8 条）。
- 分镜工作区和剪辑工作区的完整实现（只做框架和接口）。
- 移动端（以后做）。
- 3D 软件级别的建模和渲染。只做 AE 级别的 2.5D：3D 图层、摄像机、灯光。

## 里程碑

| 里程碑 | 内容 |
|---|---|
| M0 骨架 | 应用能启动并打开 GPU 窗口；空工程能保存和读取；CI 与体积检查跑通 |
| M1 更快的 AE | AE 全部基础功能：合成、各类图层、关键帧与缓动、表达式、遮罩、轨道遮罩、混合模式、形状、文字、常用效果、3D 图层与摄像机灯光、运动模糊；GPU 实时预览；渲染队列导出；插件体系 v1（声明式 GPU 效果 + 原生插件 + 脚本）；工程打包（不裁片）；AE 插件兼容的设计文档 |
| M2 交接与协同 | 导入/导回 AE 工程；打包时视频裁片；Agent 通过 MCP 操作；两人以上实时协同；历史与命名版本 |
| M3 生态 | 插件 SDK 文档与示例完善；AE 插件兼容层原型（按验证结果选定范围） |
| M4 大一统 | 分镜（Ai 式）与剪辑工作区（Premiere / 达芬奇 / Final Cut Pro 风格前端预设）在已预留的框架上实现 |
