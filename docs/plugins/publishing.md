# 打包、安装与版本

对应规格 §5.1、§6、§7、§20。

## 插件包

插件包就是一个目录，根目录有 `bae-plugin.toml`：

```text
com.example.vignette/
  bae-plugin.toml                清单（必需）
  shaders/vignette.wgsl          声明式效果的着色器
  bin/macos-aarch64/libx.dylib   原生库，每个平台一个
  bin/windows-x86_64/x.dll
  scripts/main.js                脚本入口模块
  schemas/*.json                 命令参数的 JSON Schema
  locales/zh-CN.toml             翻译（清单里的英文是默认值）
  icons/*.svg                    图标（只用自己绘制的 SVG）
  README.md、LICENSE
```

分发时可以把整个目录打成 `.baeplugin`（zip）：清单在压缩包根目录，或者在唯一的一层顶级目录里。默认最大 256 MiB。安装 `.baeplugin` 的命令（`bae plugin install`，同时是 Agent 能调用的命令）在后续版本提供；现在把插件目录复制到下面的插件目录即可。

发布前用检查工具确认没有错误：

```sh
cargo run -p bae-plugin --example check -- com.example.vignette
```

## 插件目录（作用域）

| 作用域 | macOS | Windows | 信任 |
|---|---|---|---|
| 内置（随应用） | `BAE.app/Contents/PlugIns/` | `<安装目录>\Plug-ins\` | 信任，只读 |
| 系统 | `/Library/Application Support/BAE/Plug-ins/` | `%CommonProgramFiles%\BAE\Plug-ins\` | 信任（管理员安装） |
| 用户 | `~/Library/Application Support/BAE/Plug-ins/` | `%LOCALAPPDATA%\BAE\Plug-ins\` | 安装时同意后信任 |
| 工程 | `<工程>.bae/plugins/` | 同左 | 用户信任这个工程之前不加载脚本和原生代码 |

目录里可以直接放插件目录（开发时方便），也可以用 `<插件 ID>/<版本>/` 的布局让多个版本并存。以 `.` 开头的目录会被跳过。设置 `BAE_HOME=<目录>` 时用户目录都在 `<目录>` 下。

工程里的声明式插件不需要信任确认就能加载：它们不执行本地代码，最多占用 GPU，共享工程可以直接打开。

## 哪个版本生效

同一个插件 ID 在一个进程里只有一个版本生效。宿主扫描所有目录时**只读清单**（不编译着色器、不加载库），然后：

1. 取版本号最高的；
2. 版本相同时，取更具体的作用域：工程 > 用户 > 系统 > 内置（这样工程可以自带一份固定版本）。

（按工程锁定的主版本选择、依赖不满足时回退，见规格 §6.4，后续版本实现。）

## 运行时加载、更新与卸载

- **加载**：校验清单、编译着色器，然后把效果定义注册到效果注册表（效果控件、效果和预设、Agent、AE 导入用），把实现注册到渲染器的效果库。
- **更新**：加载同一个插件 ID 的另一个版本时，先卸载旧版本再注册新版本，不需要重启。
- **卸载**：只删除这个插件注册的条目。正在渲染的帧还持有效果的引用，渲染完才释放；效果的 GPU 资源（管线、布局等）随最后一个引用一起释放。验收测试反复加载 → 渲染 → 卸载 100 次，wgpu 里存活的对象数保持不变。
- 插件效果不能覆盖内置效果或其他插件的同名效果，加载会失败并说明冲突的是谁。

## 缺失插件

工程里用到、但没有安装的插件效果：

- 数据**完整保留**（参数值、关键帧、表达式、实例状态），保存工程不会丢任何东西；
- 渲染时跳过这个效果；文档模型把它报告为缺失插件（`EffectStatus::MissingPlugin`），效果控件据此显示占位和原来的参数；
- 重新安装插件后，下次构建渲染图时自动恢复；
- 导回 AE 时按原来的 matchName 和参数原样写回。

卸载插件对已打开的工程也是这样：效果变成占位，工程数据不变。

## 兼容性承诺

插件的 `version` 是语义化版本，它同时是对**工程数据**的承诺：

- 补丁版本和次版本必须能读同一主版本的旧版本写的工程：参数 ID 不复用、不改类型；删掉的参数改成隐藏（宿主保留它存的值）；弹出菜单只在末尾追加选项；实例状态保持可读。
- 主版本可以打破这些规则，但应该提供 `[[effect.migration]]`（声明式）或迁移代码（原生）。
- 插件 ID、贡献 ID 永远不变；改名用新 ID 加 `replaces`。

`api`（插件 API 版本）是宿主对插件的承诺：同一主版本里，新宿主可以运行为旧次版本写的插件。0.x 是设计阶段，次版本之间也可能不兼容；ABI 1.0 起冻结。
